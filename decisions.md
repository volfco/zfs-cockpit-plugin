# Decision Log

- **D1 (major)** Coverage model = "complete via generic UI" (user-selected): dedicated dialogs for lifecycle ops, one generic property editor for ALL `zfs get/set/inherit` (incl. plugin/user properties), typed wrappers for every subcommand in service.ts, raw `zfs`/`zpool` console as escape hatch. Why: literal per-subcommand dialogs ≈ 3x the code for near-zero tail usage; generic mechanisms cover 100% of the surface. Ref: plan.md Define.
- **D2 (major)** Parse stable text/machine forms (`-H`, `-Hp`, `zpool status` tree) instead of OpenZFS 2.3 `--json`: JSON is 2.3-only and the target floor is 2.2, so JSON would mean dual parser paths. Ref: test/fixtures/raw/zpool-json.txt.
- **D3 (minor)** `pkg/lib` copied from the hpssa checkout (same cockpit repo stamp) rather than re-fetched from GitHub. Ref: hpssa Makefile COCKPIT_REPO_STAMP.
- **D4 (minor)** Live validation uses file-vdev scratch pools under `/tmp/zfs-fixtures/` on colum@203.0.113.139; host pools `hdd0`/`ssd1` and real disks are off limits. Ref: assumptions.md.
- **D5 (minor)** Scaffold copied from hpssa verbatim; placeholder `src/app.tsx` uses PF6 `Content` (not `Text`, which PF6 6.5.0 removed) and the build emits per-language `po.<lang>.js`/`po.manifest.<lang>.js` exactly like hpssa (no aggregate `po.js`). Ref: hpssa build.js cockpit-po-plugin.
- **D6 (major)** UI wave 1: shell + pools tab + Events/History + command log + settings (app.tsx/components, 3328 lines). Confirm-before-destructive setting (default on) gates typed-name confirmation (FormDialog `requireTyped` + danger submit); with it OFF, destructive ops run immediately with output shown. Create-pool property rows are "key=value per line" textarea (pkg/lib dynamic-list is a PropTypes JSX class — checkJs risk not worth it). draid exposed as draid1/2/3. Ref: src/components/{actions,dialogs,poolsPage}.tsx.
- **D7 (minor)** `poolImport` readonly switch maps to `-o readonly=on` (no CLI flag exists); `poolStatus` raw view calls `runZpool(['status','-P'])` because the wrapper's `parsable` maps to `-p` only; `HistoryEntry` shows time+command (`zpool history` has no user attribution). Ref: src/service.ts friction notes.
- **D8 (minor)** Send/receive UI executes local pipes/files via `sh -c` with strict single-quote escaping (`shellQuote`) — raw send streams are binary and cannot pass through cockpit.spawn text streams. Dry-run preview runs first-class via `dsSend({dryrun})`. Ref: src/components/datasetsPage.tsx (wave 2).
- **D9 (minor)** `runShell(cmd, reason)` added to service.ts (logged `sh -c` runner) so composed send/receive pipelines (D8) appear in the command log like every other operation; CommandLogEntry.bin widened to include 'sh'. Ref: src/service.ts, src/components/datasetActions.tsx.
- **D10 (minor)** UI test harness mocks the whole `src/service.ts` via esbuild onLoad replacement (export names extracted from the real module, so the 70 wrappers stay auto-covered) and builds fixture models by running the REAL parsers over embedded raw captures — the browser test doubles as parser integration. Remote Justfile recipes stay ssh-only (`live-scratch-up/down`, `fixtures-capture`); the harness itself is local and mocked. Ref: test/ui-check.mjs, test/ui/fixtures.ts, Justfile.
- **D11 (major)** Packaging parity with hpssa's post-fix state, verified by replaying the CI steps in the real containers (`ghcr.io/cockpit-project/tasks` → cockpit-zfs-1.0.0-1.fc44.noarch.rpm; `ubuntu:24.04` → cockpit-zfs_1.0.0-1_all.deb), both inspected (payload, LICENSE, metainfo, `cockpit-bridge >= 137` deps). `Makefile` VERSION fallback `1` → `1.0.0` (D12 lesson); spec Source0/1 are bare filenames (hpssa's release URLs 404 — their todo, resolved here); PKGBUILD `arch=('any')` + SPDX `LGPL-2.1-or-later` (hpssa todo); `LICENSE` added (LGPL-2.1, %license ships it). Not verified here: lintian, Arch makepkg, the opt-in `rebuild_bundle` branch. Ref: packaging/, debian/, .github/workflows/build-packages.yml.
- **D12 (minor)** Repo published to `github.com:volfco/zfs-cockpit-plugin` (branch `master`, pushed after the packaging wave); `just push` keeps the external op as a Justfile recipe per repo rules.
- **D13 (major)** Independent dual review (correctness + quality reviewers) → 17 fixes. Correctness P1s: `zpool reguid -g` argv, `zfs share` protocol operand legality (protocol only with `-a`), `zfs wait -t` reduced to the only real activity (`deleteq`), `cmdWords` now quotes every word (closes a shell-injection path through user fields), `zfs unmount -u` gets the same typed-name gate as unload-key. Reviewer-confirmed real bug: `zfs diff -H -t` emits epoch-millis rows (captured live), not ISO dates — parser fixed to handle plain/`-t`/`-t -F` forms. Also: stale-error lockout in 4 dataset panels, `POOL_LIST_COLUMNS` gained `autotrim,comment`, capability-table version corrections, `--saved` send switch removed (can't be valid for snapshot sources), `DESTRUCTIVE_OPS` + contract semantics documented as informational. Ref: src/**, test/**.
- **D14 (major)** New `test/argv-check.mjs` exercises the REAL service.ts wrappers (58 argv assertions / 32 wrappers via esbuild + recording cockpit stub) — the UI test mocks service.ts, so flag typos previously passed silently. Wired into `just check`. Also: parser-check covers the new diff + `replacing-1` captures, wrapper-check refuses vacuous passes. Ref: test/argv-check.mjs.
- **D15 (minor)** Create-pool device fields (members/log/cache/spares) switch from free-text textareas to a checkbox-dropdown multi-select (PF6 Select + chips, new FormDialog `multiselect` field; user-chosen over a dual-list or inline checklist). Disk list comes from `fetchAvailableDisks()` (`runShell('lsblk -J -b -p -o NAME,SIZE,MODEL,ROTA,TYPE,FSTYPE')`); `parseAvailableDisks` hides every device that is — or contains a partition that is — a `zfs_member` (assigned to a pool, imported or not), while disks with other filesystems stay listed (user-chosen; the Force switch is the guardrail). Pure multi-select (user-chosen): file vdevs dropped from this dialog, raw console covers them. FormDialog now initializes values only on open-transition so async-loaded option lists never wipe typed input. Independent review (reviewer subagent, no P1/P2) → 2 accepted P3 fixes (stale disk list/error cleared on dialog open, `Number()` size coercion) and the UI case extended to assert the log/cache/spare keyword assembly in the create argv. Ref: src/components/dialogs.tsx, src/zpool.ts, src/service.ts, test/fixtures/raw/lsblk.txt.
- **D16 (minor)** Release `0.1.2` tagged `v0.1.2` on 3dddc36 (lightweight, matching `v0.1.0`; the v-prefix is the repo convention — Makefile strips the v so packages carry the bare `0.1.2`). Tag+push is a `just tag <version>` recipe per the external-ops rule. Ref: Justfile, Makefile VERSION.
- **D17 (minor)** Property-edit modal picked the editor from the *current value* (`value === 'on'|'off'`), locking enum properties at `on` (compression default `on` → no zstd/lz4). Fixed by a hand-maintained `BOOLEAN_PROPS` set (atime/devices/exec/nbmand/overlay/readonly/setuid/sharesmb/zoned) that alone gets the on/off dropdown; everything else is free text (which also covers snapdir/xattr/dedup enums and user/plugin props). Risk: new pure-boolean ZFS properties must be added to the set. Released as tag `v0.1.3`. Ref: src/components/propertiesPanel.tsx.
